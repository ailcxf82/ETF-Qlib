# 04 开发计划与验收

## 1. 实施原则

先完成可信数据和固定模型闭环，再让 RDAgent 自动研发。以下为开发规格，不是已完成清单；现有 smoke train 仅能说明部分依赖和训练路径可用，不能代替这些验收。

本阶段范围包括 Python 本地工程、可复现数据快照、Ridge/LightGBM、ETF 回测、RDAgent 因子链路、多模型扩展与影子信号。暂不包括实盘账户连接、订单发送、分钟行情服务或多用户 Web 平台。

## 2. 有依赖顺序的工作包

| 工作包 | 依赖 | 主要交付 | 完成标准 |
| --- | --- | --- | --- |
| W0 工程基座 | 无 | `pyproject.toml`、版本清单、配置 schema、日志、运行 ID | 可安装包；配置错误立即报错；无密钥输出 |
| W1 数据准入 | W0 | 日历/字段/单位扫描、标准化快照、历史池、企业行为映射 | G0 通过；原数据不变，修复有证据 |
| W2 机器学习数据集 | W1 | 标签、事件区间、时间切分、预处理、10–30 个基线特征 | Dataset 满足契约；时点与标签测试通过 |
| W3 固定模型与回测 | W2 | Ridge、LightGBM、每 5 日轮动、费用/持仓账本、基准 | G1 通过；固定基线可复现 |
| W4 RDAgent 单轮 | W3 | 场景、实验构造、coder/runner、容器、反馈映射 | G2 通过；单个候选跑完或正确拒绝 |
| W5 多轮因子研究 | W4 | 候选库、配对实验、预算、缓存、断点恢复、消融 | 多轮完成并追溯；holdout 未暴露 |
| W6 模型扩展与验收 | W5 | 至少一个 XGBoost 对照、模型注册、最终验收入口 | G3 通过；所有模型共享评价协议 |
| W7 每日影子运行 | W6 | 冻结包加载、特征一致性、信号产物、监控、恢复 | G4 通过；仅输出信号，不下单 |

关键路径为 W0 → W1 → W2 → W3 → W4 → W5 → W6 → W7。W1 可能需要回到上游数据导出项目修复日历和复权；未完成不能以临时填充值跳过。工期应在 W1 扫描后，根据数据缺口与实际运行时长再估算。

### 执行清单

- [ ] 建立 `etf_ml` 包、配置 schema 和运行/产物契约，记录本机依赖版本。
- [ ] 审计并标准化原始 ETF 数据，冻结历史池与字段时间口径，通过 G0。
- [ ] 实现 h=5 标签、四类时间角色、purge 和模型预处理，建立因果性夹具。
- [ ] 跑通 Ridge/LightGBM 固定基线及 ETF 交易账本，通过 G1。
- [ ] 接入 RDAgent 场景、实验、隔离执行、runner 和结构化反馈，通过 G2。
- [ ] 实现有预算的多轮配对实验、消融、因子版本和断点恢复。
- [ ] 固定特征集比较 XGBoost 等模型，并独立执行最终留出验收，通过 G3。
- [ ] 建立冻结模型包的每日信号、异常监控和版本恢复，通过 G4。

## 3. 阶段门禁

### G0 数据可用于研究

必需条件：

1. 日历经可信来源校验，无非法日历位置；重建后逐样本价格日期映射正确。
2. OHLC、量额单位、复权关系、涨跌幅和企业行为通过校验。
3. 历史可投资池可重建；时间可用性不足的字段和标的有明确排除策略。
4. 固定数据快照和数据质量报告；原始数据前后哈希一致。
5. 冻结预测周期、调仓起点、成本、账户规模、K、风险上限、样本切分和研发预算。

产物：`data_quality.json`、`snapshot_manifest.json`、`universe.parquet`、`protocol.json` 和修复证据。G0 不能以单只 ETF 的成功读取替代全量目标范围检查。

### G1 固定机器学习基线

必需条件：

1. Ridge 和 `LGBModel` 均完成至少一个小样本集成运行，再完成正式开发折运行。
2. 最新推断行不依赖未来 label；所有模型预测索引、特征顺序与目标池一致。
3. 手工动量、等权池基准及模型策略采用一致的可交易区间、成本和账本。
4. 人工夹具核对订单、持仓、现金、费用、取整、分红、未成交与回撤计算。
5. 同环境同版本同种子重跑，在预先规定数值容差内一致；现金守恒残差与收益差异可解释。

产物：模型包、预测、交易/持仓/日收益、指标和基线报告。收益不要求为正，必须如实报告失败或无优势。

### G2 Agent 单轮集成

必需条件：

1. 不消耗 LLM 的确定性候选回放先通过，再执行配置预算内的一轮真实模型调用。
2. baseline 和 candidate 都进入 ETF workspace，所有数据读取落在研发视图。
3. 至少验证一个合法候选，以及未来引用、重复索引、全 NaN、超时四类失败候选。
4. 候选和基线拥有相同协议、样本与预算，能输出逐折增量或清晰错误。
5. Agent 不可访问 holdout 文件、API 凭据或原始数据全盘；预算与资源限制可观察。

产物：完整调用轨迹、FactorSpec、代码、执行日志、质量报告和结构化反馈。即使候选被拒绝，也可通过集成验收。

### G3 研究冻结与独立验收

工程条件：冻结特征集，至少完成 LightGBM、Ridge、XGBoost 的同协议比较；通过消融与成本压力测试；保留所有 trial 记录；独立入口读取冻结模型与协议。

投资研究条件：在冻结前设定最终验收阈值，分别报告绝对收益、基准超额、回撤、成本和稳定性。阈值未满足时标记研究未通过，不抬高结论，也不删除失败样本。

最终 holdout 验收仅执行冻结候选的既定协议。若之后根据结果调整方案，该时间段已被使用；后续版本需要新的留出或前瞻期。技术性失败重跑需保留原因与参数一致证据，不能以“修 bug”为由反复改变研究目标。

### G4 每日影子运行

工程条件：建议至少连续 10 个真实交易日，覆盖两个调仓节点（边界按冻结日历确定）；验证行情延迟、漏数、同日重复触发、进程中断和旧版本恢复。影子周期用于运行稳定性，不用于宣称长期投资有效性。

产物：日信号、目标仓位、输入版本、跳过原因和监控记录。最终研究未通过时可以继续影子验证技术链路，但产物必须标记为实验状态，不能升级成可投资建议或实盘版本。

## 4. 必需测试矩阵

| ID | 用例 | 应有结果 |
| --- | --- | --- |
| T01 | 日历含周日或重复日期 | 数据准入失败；不可继续编码/训练 |
| T02 | 重建日历后的 bin 位置 | 同一有效日期的价格值保持一致 |
| T03 | 价格差误填 `$change`、量额倍率错误 | 语义校验报错或明确阻止正式回测 |
| T04 | 分红/拆分跨持有期 | 现金、份额与收益处理一致，无重复收益 |
| T05 | 截断/扰动未来数据 | 历史纯因果因子值保持不变 |
| T06 | 打乱 ETF 排列或加入其他 ETF | 纯时序因子无串组污染 |
| T07 | train 尾部标签跨 early_stop 起点 | 对应训练样本被剔除 |
| T08 | 重训日期标签尚未成熟 | 不进入训练或处理器拟合 |
| T09 | 最新日期缺失未来标签 | 仍产生合法的最新预测 |
| T10 | 候选大量缺失/全常数 | 门禁失败或正确处理，比较索引不被偷偷缩小 |
| T11 | t 日信号和 t+1 成交 | 只延迟一个交易步，5 日标签与持有间隔对齐 |
| T12 | 停牌/卖出受限/退市持仓 | 不凭空消失，保留估值及现金占用并输出状态 |
| T13 | 买入卖出手续费和最小单位 | 与人工账本逐项一致 |
| T14 | Agent 访问 holdout/宿主路径 | 访问失败，不在异常日志泄露敏感内容 |
| T15 | 因子死循环/内存超限 | 任务被终止并标记 failed，不污染下一轮 |
| T16 | 数据版本变化但因子源码不变 | 缓存失效，不复用旧输出 |
| T17 | 两个实验交错结束 | 各自按 run_id 读取自己的结果 |
| T18 | 保存/加载模型包 | 同一输入预测在规定容差内一致 |
| T19 | 特征列缺失/顺序变化 | 重排并核验或明确失败，不静默错位 |
| T20 | 同日重试与中断恢复 | 运行幂等、产物完整，失败不覆盖成功版本 |

测试以合成小数据、人工事件夹具和有限本地 ETF 样本分层进行。持续集成不调用付费 LLM；真实 LLM 与完整历史回测按里程碑运行。新增模型只扩展相关契约测试，不为无行为变化反复跑所有昂贵实验。

## 5. 运行手册规格

以下为未来 CLI 规格，当前尚不存在这些命令。实现时所有命令都支持 `--config`、`--run-id` 和清晰退出码；默认参数不得触发自动下单。

| 入口 | 作用 | 失败策略 |
| --- | --- | --- |
| `python -m etf_ml.cli audit-data` | 只读扫描原始 ETF 数据 | 返回问题清单，阻止不合格快照 |
| `python -m etf_ml.cli build-data` | 构建标准化研发/验收视图 | 写到临时输出，成功后原子发布 |
| `python -m etf_ml.cli baseline` | 固定特征的 Ridge/LightGBM 回测 | 保留独立失败实验 |
| `python -m etf_ml.cli research-factor --max-trials 1` | 受预算限制的研发 | 达到预算/超时后保存并退出 |
| `python -m etf_ml.cli compare-models` | 冻结特征下的模型比较 | 不自动提升获胜模型 |
| `python -m etf_ml.cli evaluate-holdout` | 独立最终验收 | 输出版本化结论；不回传 Agent |
| `python -m etf_ml.cli daily-signal` | 加载冻结包生成信号 | 数据不完整时明确跳过 |

当前已有诊断入口为 `scripts/check_etf_environment.py`，其默认路径已正确。后续将其结果拆分为环境可用性与框架 G0–G4 状态，不再仅因默认环境名不同就笼统报告“需要适配”。

每次运行目录至少包含 manifest、配置、stdout/stderr、状态、指标、产物列表和错误原因。退出码区分配置错误、数据未就绪、执行失败与质量未通过，避免将“策略没有改善”误报成程序崩溃。

每日监测输入截止时间、特征覆盖、分布变化、预测稳定性、持仓集中度和生成延迟。缺少实际成交数据时不能把回测估计收益标为实盘收益。版本恢复加载上一个完整冻结包和对应特征定义，而不是只替换模型权重。

## 6. 风险、待决策项与默认处理

| 项目 | 当前状态/默认值 | 何时必须解决 |
| --- | --- | --- |
| “LBGLight” 名称 | 按 LightGBM / Qlib LGBModel 理解 | 若用户指其他模型则修订注册项 |
| ETF 范围 | 暂按境内股票 ETF；跨资产接口保留 | G0 冻结前 |
| 数据单位/复权/日历 | 发现待核实项，不能假定已修复 | W1，硬依赖 |
| NAV 发布时间 | 第一版不使用不可靠 NAV 衍生因子 | 引入该字段前 |
| 预测和调仓 | h=5，每 5 个交易日；h=1 诊断对照 | G0 冻结前 |
| 基准 | 建议研究池等权 + 可用宽基 ETF；具体标的待核实 | G0 冻结前 |
| 账户规模、K、费用、风险上限 | 不填伪精确的通用值；共同决定可交易性 | G0 冻结前 |
| API 预算 | 每轮与总预算都需显式配置；当前不启动调用 | W4 真实调用前 |
| 2026 留出独立性 | 需检查既有使用历史 | W1 切分冻结前 |
| 分类和历史池可信性 | 不能凭当前元数据倒推所有历史 | W1 |
| Docker 可用性 | 历史日志曾出现不可用，需运行时预检 | W4 |
| 高度相关的 ETF 样本 | 按日期/时间块统计，补充跟踪组结果 | W3–W6 |
| 反复选择的过拟合 | 固定研发预算与验证协议，保留最终独立验收 | W4–W6 |

## 7. 交付完成定义

文档阶段完成：需求可追踪到模块与验收，模型与因子契约一致，尚未确认的参数有决策时点。

工程阶段完成：G0–G4 的技术门禁全部有证据，模型包与数据可追溯，异常处理和恢复可验证。

投资研究完成：独立验收按预先冻结规则给出通过或未通过结论，不能用工程成功替代投资效果。未通过时保留研究结果并设计新的前瞻检验，而不是循环挑选测试区间。
