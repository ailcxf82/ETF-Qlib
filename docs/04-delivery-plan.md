# 04 开发计划与验收

## 1. 实施原则

先完成可信数据和固定模型闭环，再让 RDAgent 自动研发。以下为开发规格，不是已完成清单；现有 smoke train 仅能说明部分依赖和训练路径可用，不能代替这些验收。

本阶段范围包括 Python 本地工程、可复现数据快照、Ridge/LightGBM、ETF 回测、RDAgent 因子链路、多模型扩展与影子信号。暂不包括实盘账户连接、订单发送、分钟行情服务或多用户 Web 平台。

### 已确认参数（2026-09-13）

- 范围：A 股场内现有正常运营的 ETF，第一版按跟踪境内 A 股的股票 ETF 识别；当前池留存时点证据，历史池按当时已知状态重建。
- 主基准：沪深300指数，默认价格指数口径；初始账户资金：人民币 500,000 元。
- 单边滑点：0.03%（`0.0003`），通过买入价上移、卖出价下移计入一次；佣金最新确认为0.03%（0.0003），按逐笔单边成交额计收；暂不另加最低费用。
- 时间切分：采用 02 §4.2 的五折扩展训练窗时序方案；2026 年为条件性最终留出候选，需核实独立性和覆盖后固化日期边界。
- 用户委托常规设定：K=0.05选当前可买候选前5%（向上取整、非空至少1只），目标等权；流动性20%为执行日前20日均成交额参与上限，同日同标的双向累计；风险明确为最大回撤12%。LLM费用已明确不设上限，首轮候选上限仍为1。
- 调仓改为月中和月末；规划默认执行日为15日或之前最近交易日、月末最后交易日，用前一交易日收盘后信号。h=5 保留为预测任务，不再与持有间隔等同。
- 参数确认不代表 G0 通过；数据治理、歧义参数口径、最低费用、其他风险约束及交易日映射仍须完成准入检查与冻结。

| 工作包 | 依赖 | 主要交付 | 完成标准 |

| W0 工程基座 | 无 | `pyproject.toml`、版本清单、配置 schema、日志、运行 ID | 可安装包；配置错误立即报错；无密钥输出 |

| W3 固定模型与回测 | W2 | Ridge、LightGBM、月中/月末轮动、费用/持仓账本、基准 | G1 通过；固定基线可复现 |
| W4 RDAgent 单轮 | W3 | 场景、实验构造、coder/runner、容器、反馈映射 | G2 通过；单个候选跑完或正确拒绝 |
| W5 多轮因子研究 | W4 | 候选库、配对实验、预算、缓存、断点恢复、消融 | 多轮完成并追溯；holdout 未暴露 |

## 3. 阶段门禁

### G0 数据可用于研究

数据来源按用户确认的 Tushare 接受。准入记录接口、下载参数和导出映射，只验证字段单位、日期映射、覆盖、复权/分红及时间隔离；已通过的证据复用，仅异常进一步追查，不逐条跨来源复验。耗时的完整来源追溯可后补，工程开发和技术测试继续；实际数据缺失或映射错误仍须修复后才能通过真实数据正式 G0。

必需条件：

1. 日历经可信来源校验，无非法日历位置；重建后逐样本价格日期映射正确。
2. OHLC、量额单位、复权关系、涨跌幅和企业行为通过校验。
3. 历史可投资池可重建；时间可用性不足的字段和标的有明确排除策略。 未知成员可在诊断中明确排除，正式完整目标快照须覆盖全部实时报价的历史分类/可用状态；不得隐式移除有报价但未知成员后冒称全池G0。
4. 固定数据快照和数据质量报告；原始数据前后哈希一致。
5. 冻结预测周期、调仓起点、成本、账户规模、K、风险上限、样本切分和研发预算。

产物：`data_quality.json`、`snapshot_manifest.json`、`universe.parquet`、`protocol.json` 和修复证据。G0 不能以单只 ETF 的成功读取替代全量目标范围检查。

### G1 固定机器学习基线

必需条件：

1. Ridge 和 `LGBModel` 均完成至少一个小样本集成运行，再完成正式开发折运行。
2. 最新推断行不依赖未来 label；所有模型预测索引、特征顺序与目标池一致。
3. 手工动量、等权池基准及模型策略采用一致的可交易区间、成本和账本。
4. 人工夹具核对订单、持仓、现金、费用、取整、分红、未成交与回撤计算。
5. 同环境同版本同种子重跑，在预先规定数值容差内一致；现金守恒残差与收益差异可解释。

产物：模型包、预测、交易/持仓/日收益、指标和基线报告。收益不要求为正，必须如实报告失败或无优势。

### G2 Agent 单轮集成

必需条件：

1. 不消耗 LLM 的确定性候选回放先通过，再执行配置预算内的一轮真实模型调用。
2. baseline 和 candidate 都进入 ETF workspace，所有数据读取落在研发视图。
3. 至少验证一个合法候选，以及未来引用、重复索引、全 NaN、超时四类失败候选。
4. 候选和基线拥有相同协议、样本与预算，能输出逐折增量或清晰错误。
5. Agent 不可访问 holdout 文件、API 凭据或原始数据全盘；预算与资源限制可观察。

产物：完整调用轨迹、FactorSpec、代码、执行日志、质量报告和结构化反馈。即使候选被拒绝，也可通过集成验收。

### G3 研究冻结与独立验收

工程条件：冻结特征集，至少完成 LightGBM、Ridge、XGBoost 的同协议比较；通过消融与成本压力测试；保留所有 trial 记录；独立入口读取冻结模型与协议。

投资研究条件：在冻结前设定最终验收阈值，分别报告绝对收益、基准超额、回撤、成本和稳定性。阈值未满足时标记研究未通过，不抬高结论，也不删除失败样本。

最终 holdout 验收仅执行冻结候选的既定协议。若之后根据结果调整方案，该时间段已被使用；后续版本需要新的留出或前瞻期。技术性失败重跑需保留原因与参数一致证据，不能以“修 bug”为由反复改变研究目标。

### G4 每日影子运行

工程条件：建议至少连续 10 个真实交易日，覆盖两个调仓节点（边界按冻结日历确定）；验证行情延迟、漏数、同日重复触发、进程中断和旧版本恢复。影子周期用于运行稳定性，不用于宣称长期投资有效性。

产物：日信号、目标仓位、输入版本、跳过原因和监控记录。最终研究未通过时可以继续影子验证技术链路，但产物必须标记为实验状态，不能升级成可投资建议或实盘版本。

## 5. 运行手册规格

以下为 CLI 规格；audit-data、build-data、baseline、research-factor、freeze-features、compare-models、freeze-model、evaluate-holdout、daily-signal、activate-model、restore-model 已有工程实现，当前证据见 05。所有入口应支持 `--config`、`--run-id` 和清晰退出码；默认参数不得触发自动下单。

| 入口 | 作用 | 失败策略 |
| --- | --- | --- |
| `python -m etf_ml.cli audit-data` | 只读扫描原始 ETF 数据 | 返回问题清单，阻止不合格快照 |
| `python -m etf_ml.cli build-data` | 构建标准化研发/验收视图 | 写到临时输出，成功后原子发布 |
| `python -m etf_ml.cli baseline` | 固定特征的 Ridge/LightGBM 回测 | 保留独立失败实验 |
| `python -m etf_ml.cli research-factor --max-trials 1` | 受预算限制的研发 | 达到预算/超时后保存并退出 |
| `python -m etf_ml.cli freeze-features --session <session.json>` | 全部新增因子组复核并发布研究特征冻结包 | 证据不足、组无增量或硬约束超限时不发布 |
| `python -m etf_ml.cli compare-models --snapshot <snapshot> --frozen-features <freeze>` | 冻结特征下的模型比较 | 不自动提升获胜模型 |
| `python -m etf_ml.cli freeze-model` | 显式选择模型/开发折/种子，冻结完整版本 | 要求选择理由；不自动晋升或读取留出 |
| `python -m etf_ml.cli evaluate-holdout --frozen-model <model-version>` | 独立最终验收 | 绑定既定候选与阈值、禁止重叠留出重用；不回传 Agent |
| `python -m etf_ml.cli daily-signal` | 加载显式冻结包或已启用影子版本生成信号 | 数据不完整时明确跳过；成功日信号不可覆盖 |
| `python -m etf_ml.cli activate-model` | 显式启用完整冻结包用于影子推断 | 需要选择理由；不更改投资验收状态 |
| `python -m etf_ml.cli restore-model` | 恢复上一个完整影子版本 | 需要理由；拒绝退休或运行环境不兼容版本 |

当前诊断入口 `scripts/check_etf_environment.py` 已分离环境可用性与框架 G0–G4 状态；`--config`运行只读准入预检，`--json`输出单份结构化报告。环境或smoke成功不提升阶段门禁：G0仍须完整验证，G1–G4未执行时为not_assessed。默认Conda环境名不同不再误报缺适配器，模块存在检查也不替代运行契约测试。`--docker-qlib`使用已验证固定digest、--pull never、--network none和只读数据挂载。退出码1为环境失败、2为配置错误、5为框架预检阻塞，0也不表示G0–G4通过。真实证据见artifacts/environment_delivery_report.json。

每次运行目录至少包含 manifest、配置、stdout/stderr、状态、指标、产物列表和错误原因。退出码区分配置错误、数据未就绪、执行失败与质量未通过，避免将“策略没有改善”误报成程序崩溃。

每日监测输入截止时间、特征覆盖、分布变化、预测稳定性、持仓集中度和生成延迟。缺少实际成交数据时不能把回测估计收益标为实盘收益。版本恢复加载上一个完整冻结包和对应特征定义，而不是只替换模型权重。
