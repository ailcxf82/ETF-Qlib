# 02 数据与机器学习规范

## 1. 数据源、快照和准入

原始数据路径使用项目约定的 `D:\qlib_data\etf_qlib_data`。第一次开发先全量只读扫描，再将校正结果写入项目新目录。当前已知日历范围约为 2020-01-01 至 2026-09-04，文件日期不代表每只 ETF 全段都有有效行情。

| 检查对象 | 必须验证 | 不合格处理 |
| --- | --- | --- |
| 交易日历 | 与权威交易日历一致、唯一、有序；区分行情日期和 NAV 日期 | 阻止生成可回测快照；修复并重建所有位置索引相关 bin |
| 代码与索引 | 使用实际代码形式，如 `510300.SH`；日期/代码唯一 | 输出冲突清单，禁止静默保留随机记录 |
| OHLC | 有限且为正、价格区间合理、异常跳变可解释 | 隔离异常；按已知事件处理，不任意截断价格 |
| 复权 | 原价、研究价格、成交价格、复权因子关系一致 | 缺失时阻止正式回测，不统一填 1 掩盖问题 |
| 成交量和金额 | 明确原单位，转换后成交额与量价关系合理 | 先核对源数据说明；不凭数值大小自动换算 |
| 涨跌幅 | `$change` 明确为收益率小数；除权基准价正确 | 不能将价格差直接作为涨跌幅 |
| 暂停交易 | 缺失、停牌、零成交、无报价可区分 | 用 tradability 标记，不前向填充成可交易行情 |
| 历史元数据 | 上市、退市、分类、跟踪指数的有效区间及信息可用时间 | 缺失关键分类时排除该标的或阻止该研究范围 |
| 基准 | 覆盖目标区间、与组合收益口径一致 | 不自动替换成不存在的股票指数 |

`DataSnapshot` 至少记录 `snapshot_id`、源路径、文件哈希清单、日历哈希、代码清单、各字段覆盖率、单位、修复日志、生成时间、数据截止日期和治理代码版本。研发数据与留出数据分别导出并分配访问权限。

若只有既有 bin 可用，先用旧日历正确还原带日期的表格，再按可信交易日历重新编码；不能直接编辑原 `day.txt`，否则 bin 的偏移可能全部错位。必须核验重建前后同一有效交易日的价格一致。

## 2. 数据契约

### 2.1 行情、研究价格与企业行为

内部标准化表显式区分 `raw_open/raw_close`、`adj_open/adj_close`、`adjustment_factor`、`volume_shares`、`amount_currency`、`return_1d` 和交易限制标记。ETF 分红、拆分合并等事件要有可核查的映射。

研究因子使用连续可比的研究价格；成交与费用必须还原到真实价格、真实份额。在适配 Qlib 时保留它要求的价格/`$factor`/成交量换算关系，并用企业行为夹具验证账本。不同时把复权收益和现金分红重复计入净值。若采用原价 + 因子 1 的模式，必须另外实现企业行为账本，不能视作默认捷径。

仅在源定义确认后，才可将“百分数涨跌幅 / 100”映射到 `$change`。不能未经确认用复权收盘价比值替代官方除权参考价口径。Qlib 文档说明了价格与复权因子的换算关系，具体导出需与本机 Exchange 一起验收。[Qlib 数据文档](https://qlib.readthedocs.io/en/latest/component/data.html)

延期到账现金分红在除息日计入应收权益，在付款日转为可用现金；除息与到账不能重复计收益，待到账款项不可用于买入。交易账本分别记录现金、应收、份额和权益；登记日资格按实际登记日收盘份额记录，支持非相邻登记日；缺少必要持仓历史时明确拒绝。实现与技术证据见06和05。

份额执行的 `exact` 模式仅支持乘积为整数的转换；非整数乘积须有实际分配明细，否则拒绝。来源可为明确“精确分配”的公告，或公告直接给出的整数乘法公式；后者不宣称已知尾数取整方法，也不映射为floor/ceil。实际Qlib和独立账本使用同一拒绝规则。

### 2.2 历史可投资池

用户已确认目标为 A 股场内现有正常运营的 ETF，第一版按跟踪境内 A 股的股票 ETF 识别。每日信号使用当日正常运营的池；历史研究按当时可知的分类和运营状态重建，不把当前存续名单作为全历史成员。只有当前存续数据时，需记录幸存者偏差并补齐历史证据，不能据此通过完整历史池验收。

输出按交易日变化的 `eligible`、`buyable`、`sellable`、`tracking_group` 和剔除原因。另保存 `buy_reason`、`sell_reason`：买入原因包含资格过滤，卖出原因独立于新买资格，允许不再合格的已有持仓退出。缺报价、零成交、未知成交量、停牌、未知暂停状态、方向禁止及未知方向状态分别记录；缺行情日不沿用上日原因。数值面板保留 `buy_block_code`、`sell_block_code`，用于在布尔未知值转为禁止后保留来源差别，不进入模型特征。训练 eligibility 使用决策时点已知的上市时长、历史成交额和分类，执行 buyable/sellable 使用模拟成交时点确实能获得的交易状态。

初始研究参数建议：至少 60 个交易日上市历史、20 日历史成交额过滤、同一跟踪指数分组。用户委托常规设定，流动性20%固定为执行日前20日均成交额的参与上限，资格筛选独立；其口径与账户规模一起在 G0 冻结，不能使用全样本平均成交额挑选 ETF。训练可保留多只同组 ETF，但模型评价、样本权重和持仓必须防止重复标的主导结论。

已有 `history_effective_start_date/end_date` 或名为 history 的文件不自动证明它是 point-in-time 数据。必须核实这些日期的生成方式，以及历史分类是否由当前信息回填。无法恢复历史信息时，应记录限制，缩小范围或建立前瞻样本。

### 2.3 特征、标签、预测

| 对象 | 索引 | 内容 | 约束 |
| --- | --- | --- | --- |
| 原始日频特征 | `(datetime, instrument)` | 数值特征列 | 唯一、有序、只用当时可知信息 |
| Qlib 学习表 | 同上 | `('feature', name)`；`('label', 'LABEL0')` | 标签单列；元数据不能混入数值特征 |
| 因子侧写 | `factor_id` | 定义、可用字段、窗口、单位、适用池、代码哈希 | 与特征文件一一关联 |
| 标签事件表 | `(datetime, instrument)` | 信号时点、入场时点、结束时点、成熟时点 | 驱动 purge 和训练截止过滤 |
| 模型预测 | `(datetime, instrument)` | `score` | 附带模型/数据/特征版本和 horizon |
| 组合输出 | `(execution_datetime, instrument)` | 目标权重、订单意图、约束原因 | 权重含现金；不可交易持仓持续记账 |

内部可使用 Parquet；面向本机 RDAgent 的适配器按需要导出 `daily_pv.h5` 和 `result.h5`。格式兼容不能替代时点、单位与索引检查。

### 2.4 每日涨跌停旁路
货币ETF不能沿用普通现金分红映射：同基金不同份额类别须按各自规则识别。零金额且缺关键日期的收益汇总不证明无收益；不得填造除息日或套用其他类别公告。纳入研究池时须取得类别专属逐日收益及其披露时点，覆盖非交易日，并实现应计收益账户、取整/份额兑付和卖出结清规则；行情收益与账户收益不能重复入账。核心 `data.money_income` 已实现显式basis_shares/par_value标准化与自然日覆盖：保留NAVTYPE/SDATE指示的原收益区间、拒绝重叠及错误单位，七日年化不参与日收益算术；`require_daily_money_income`拒绝将多日汇总当作逐日收益。真实三只历史收益已归档；`backtest.income`已实现固定单位收益规则与未付收益账户。按真实闭仓份额计权利，未付现金按面值换成等价份额后参与复利，达到面值整数倍时兑付份额；部分卖出保留收益，实际全卖结清正/负余额。Qlib在成交后、日收益/历史持仓采样前入账，非交易日收益在下一开盘前按前次持仓补记；独立重放核对余额、现金、份额及每日权益，保存income_balances/income_postings。`evaluate`显式接收income和income_rules；必须覆盖所有自然日并提供上海本地available_time，晚于下一执行开盘的收入拒绝参与后续定仓。默认exact拒绝缺少分币尾数分配证据；truncate_cent仅在显式allow_income_rounding_proxy技术授权下运行，并记录残余和proxy状态，不能代替真实来源资格。收益来源契约位于`data.income_supplement`，`backtest.income`兼容导出IncomeRule；DataSpec.income_path可声明标准化逐日parquet。每条收入含evidence_id和available_time；attrs.income_rules逐标的明确rule_id、basis_shares、par_value、compound_unpaid、convert_at_par、rounding及规则evidence_id/available_time，规则须在首个收益期前可用。attrs.primary_evidence按evidence_id绑定相对path、https url及sha256；数据与规则须引用已验证文件，禁止越界路径。正式快照拒绝汇总推日、未来披露、技术截尾proxy及同标的未版本化现金/份额事件；保存完整及research/holdout收入视图，研发视图不携带未来原文证据。标准固定模型、候选配对、辅助基线和费用压力共用快照收入；独立留出读取留出视图。每日纸面账户由调用方提供已兑付/事件调整后的收盘份额、income_balances、income_rule_ids及当日income_as_of；缺当前余额、规则不符、非分币金额或全卖后遗留收益拒绝，不再次自动应计。余额计入权益/风险与income_weight，不变为买入现金；冻结开发期收入及规则改写拒绝。两只合并区间的逐日明细、最终尾数分配及历史披露时点仍待补，真实收益输入尚未合格发布；启用货币可投资池还须另验含应计收益的总回报标签，不以本轮股票基线合成夹具替代。

可选 `DataSpec.source_revisions_path` 声明显式原价/因子修订旁路。原provider保持只读；在原始factor旁路导入之后、归一化之前核对原文件哈希、逐字段原值、两份未复权日线响应的标的/日期/OHLCV及金额显示精度。替换close后按来源前收盘参考价重算涨跌字段，并明确修订量额；仅当独立前收盘与下一日前收盘参考价一致且源分红未声明该日现金行为时，移除绑定的错误factor边界，保留其他倍率。后续事件关系及独立账本仍须通过，不生成现金/份额事件或调整容差。当前使用修订后的历史行情版本，实际发现/下载时间保存于回执，不伪造历史下载可用时点；PIT分类另行验证。快照记录修订内容及全部证据哈希，来源、单位、原值、报价口径、边界或证据缺失/冲突时拒绝。

可选 `DataSpec.limits_path` 声明每日原价上下限。输入为 `(datetime,instrument)` 唯一有序索引及up_limit/down_limit/available_time，须覆盖每个有效报价，并与绑定原响应的价格、日期和时点映射精确一致；部分缓存不能替代完整目标池。

availability_policy区分recorded_receipt与source_documented_schedule。前者须提供原响应中的完整时区收件时间；后者冻结说明、上海本地钟点，明确只是按源更新说明采用的历史工程政策，不证明逐条实际收件。开盘时仍不可用会禁止两方向并阻止合格快照发布。当天开盘涨停禁止买入、跌停禁止卖出；已有暂停/无报价/方向限制不被覆盖。Qlib进一步检查滑点后的成交价必须处于当日价格上下限内。输入和原响应全部绑定快照哈希，约束字段不进入模型特征。

## 3. 时间、标签与预处理

### 3.1 默认预测任务

以有效交易日序列中的 t 表示决策日，t 日收盘数据完成入库后计算特征，t+1 日开盘执行。预测 h=5 个交易日的开盘到开盘收益：

`y(t,i) = P_adj_open(t+1+h,i) / P_adj_open(t+1,i) - 1`

Qlib 表达式示意为 `Ref($open, -6) / Ref($open, -1) - 1`，前提是 `$open` 已映射为一致的研究价格。h=1 的诊断任务使用 `Ref($open, -2) / Ref($open, -1) - 1`。

主标签选择原始未来收益，第一版不默认做 label 横截面标准化。相对基准/同组超额收益、波动率归一化收益作为独立标签实验，均需新建协议和比较基线。模型输出作为排序分数；收益回测使用未标准化的真实收益口径。

用户已将调仓频率改为每月月中和月末，替代每 5 个交易日。日期映射暂按当月15日或之前最近交易日、当月最后交易日作为执行日；使用执行日前一交易日收盘后完成的信号，不额外延迟一交易步。同月执行日期重复时去重，映射在 G0 写入冻结日历。h=5 保留为当前预测任务，不能再视为实际两次调仓的持有期；若改用下一调仓收益标签，须另建 LabelSpec 和协议。每天计算分数可支持诊断，但只在规定调仓时点产生新仓位。5 日重叠标签的均值不能作为日收益序列直接年化，组合日收益须来自实际模拟持仓账本。

### 3.2 信息可用时间

- 为每类数据定义 `event_time`、`available_time` 和摄取完成时间；按最晚约束判断是否可用。
- NAV/公告/宏观数据必须按公布时间做 as-of join。只有日期没有时间时采用经过说明的保守滞后策略；无法确认的字段不进入 MVP。
- 原因子不读取 label、未来市场池或留出统计。未来价格仅可在独立标签生成器中使用。
- 禁止跨 ETF 的无分组 rolling/shift，禁止反向填充、居中窗口和全样本拟合归一化。
- 检查默认策略是否已经读取前一交易步的预测。集成测试必须确认只延迟一次。

### 3.3 预处理与模型输入

`DataHandlerLP` 配合 `DatasetH` 实现表格模型数据路径。学习态与推断态分别处理：学习态剔除未成熟/缺失标签；推断态不能因未来标签缺失而删除最新特征行。对应 Qlib 的 `DK_L`/`DK_I`，实现时核验处理器加载路径。[Qlib 模型数据接口](https://qlib.readthedocs.io/en/latest/component/model.html)

树模型保留可解释数值特征，非有限值转换成缺失并记录质量；Ridge 在训练段拟合缺失填充与缩放，推断复用。去极值阈值、缩放参数、特征筛选和 PCA 等都只能在对应训练段拟合。横截面标准化如启用，只能用当日可见的合格池，并明确小截面退化处理。

不能对所有组合因子直接 `dropna()` 使候选模型的困难样本消失。每组对照固定目标样本集合、缺失策略与最终评价索引；覆盖不足本身作为候选失败原因。

## 4. 验证协议与防止选择偏差

### 4.1 四种时间角色

| 角色 | 用途 | 可被 Agent 使用 |
| --- | --- | --- |
| `train` | 拟合预处理器与模型 | 可通过研发输入视图使用 |
| `early_stop` | 训练早停及受限调参 | 可见，属于开发数据 |
| `selection` | 因子和模型比较、反馈 | 可见；反复使用会产生选择偏差 |
| `holdout` | 最终独立验收 | 不可见，不反馈、不进入 RAG |

本机 Qlib 模型将 `valid` 用于训练验证。适配器将业务 `early_stop` 映射为 Qlib `valid`，研发预测阶段将 `selection` 映射为所需 segment。若标准 Record 组件硬编码 `test`，研发 workspace 内的 `test` 只能指向 selection，并在 manifest 写明业务角色。最终 holdout 使用另一入口和另一个数据视图。

### 4.2 已采用的常规时序滚动切分

用户于 2026-09-13 确认时间切分按常规规划，采用以下扩展训练窗、半年早停、半年研发选择的五折方案。边界在 G0 根据数据覆盖映射到真实交易日，2020 年初保留特征预热区间；缺失区间需如实报告，不得根据候选收益改变切分：

| 折 | Train | Early stop | Selection |
| --- | --- | --- | --- |
| A | 2020–2022 | 2023 上半年 | 2023 下半年 |
| B | 2020–2023 上半年 | 2023 下半年 | 2024 上半年 |
| C | 2020–2023 | 2024 上半年 | 2024 下半年 |
| D | 2020–2024 上半年 | 2024 下半年 | 2025 上半年 |
| E | 2020–2024 | 2025 上半年 | 2025 下半年 |

将 2026 年至冻结快照有效截止日的区间作为最终留出候选，前提是它尚未被用于既有策略挑选。只读检查部分字段不等于收益调优，但仍须核对历史实验记录；若该段已经用于选择，改用新的前瞻样本，不把它重新命名成“独立测试”。

早期阶段可仅使用较少开发折验证工程性能，正式因子选择使用冻结的全部折。后续折的训练可以纳入历史折数据，因为这些信息在当时已经发生；所有折仍属于开发协议，不宣称反复检验后的 selection 是无偏外推结果。

### 4.3 边界与统计要求

按标签的实际结束/可用时点，剔除跨越下一分段起点的样本；不要只按日历机械删除 h 行。每次历史重训还要过滤当时标签尚未成熟的样本。滚动验证只使用过去拟合，禁止随机打乱 train/test。

扩展到有未来训练段的交叉验证时，必须另行实现事件区间重叠剔除和 embargo；第一版不采用这种交叉验证。特征预热可以读取分段之前的历史，但不能让处理器见到分段之后的数据。

统计按日期或连续时间块聚合，不把相关 ETF 行当作独立样本。5 日标签使用足够长度的时间块估计不确定性，报告逐折结果、有效日期数、截面大小和尝试次数。验证期被反复用于研发的偏差要保留在报告中。

## 5. LightGBM 与其他模型

### 5.1 模型矩阵

| 模型 | Qlib 接入 | 阶段 | 目的 |
| --- | --- | --- | --- |
| Ridge | `qlib.contrib.model.linear.LinearModel`，`estimator: ridge` | 必选基线 | 检验简单线性信号与非线性增益 |
| LightGBM | `qlib.contrib.model.gbdt.LGBModel`，`loss: mse` | 必选主模型 | 主训练、因子增量筛选 |
| XGBoost | `qlib.contrib.model.xgboost.XGBModel` | 首选扩展 | 固定特征下的树模型对照 |
| CatBoost | `qlib.contrib.model.catboost_model.CatBoostModel` | 可选 | 类别特征与不同树结构的对照 |
| LSTM/GRU 等序列模型 | 配套 Qlib 模型及序列 Dataset | 后续 | 仅在样本量与时序任务需要时启用 |
| 按日排序模型 | 自定义 Qlib Model wrapper | 后续 | 按日期分组学习 ETF 相对排序 |

上述前四个类路径已在本机包源码核对。Ridge、LightGBM、XGBoost 已有合成训练/最新推断/保存加载与同样本回测测试；XGBoost 锁定3.2.0，并通过 etf_ml.models.xgboost.ETFXGBModel 在 Qlib XGBModel 上显式使用最佳早停轮数。CatBoost 依赖、正式开发折和完整冻结特征比较尚待阶段验收。统一模型注册项包括类路径、构造参数、fit 参数、输入类型、缺失策略、标签类型、随机种子及预算；不能把所有模型的参数直接套到 `LGBModel` 上。

本机 `LGBModel` 的 `loss` 构造参数接受 `mse`、`binary`，准备数据时要求单列标签。默认实现不构造按日期的 ranking group。加入 LambdaRank 时需新 wrapper，按日期组织 group、正确编码 relevance label 并检查分组顺序；不能只将 `loss` 或 `objective` 改名。排序组要求见 [LightGBM Ranker](https://lightgbm.readthedocs.io/en/stable/pythonapi/lightgbm.LGBMRanker.html)。

### 5.2 起始配置片段

以下仅是模型片段，不是可直接运行的完整 `qrun` 配置；还需适配器生成 dataset、segments、record 和回测政策。参数是保守起点，不是优化结果。

```yaml
model:
  class: LGBModel
  module_path: qlib.contrib.model.gbdt
  kwargs:
    loss: mse
    learning_rate: 0.03
    num_leaves: 15
    max_depth: 4
    min_data_in_leaf: 100
    colsample_bytree: 0.8
    subsample: 0.8
    subsample_freq: 1
    lambda_l1: 0.0
    lambda_l2: 10.0
    num_boost_round: 500
    early_stopping_rounds: 50
    num_threads: 4
    seed: 42
    deterministic: true
    force_col_wise: true
```

确认训练样本规模支持叶子样本量，过小的 smoke 样本可使用单独低复杂度配置，不能把 smoke 配置的效果当正式比较结果。CPU 确定性参数和 seed 用于同环境复现，不保证跨依赖版本位级一致。`subsample_freq` 与 `subsample` 配套使用。[LightGBM 参数说明](https://lightgbm.readthedocs.io/en/stable/Parameters.html)

Ridge 使用 `include_valid=False`，只在 train 拟合。XGBoost 的训练轮数和早停参数在本机属于 fit 参数；注册器区分构造与训练参数。模型包记录训练轮数、最佳轮数及编号基点；XGBoost 预测显式使用 [0, best_iteration+1)，避免默认使用早停后保留的树。受控夹具已验证其输出与全部树不同。LSTM/GRU 必须声明输入张量形状、序列长度、特征顺序和窗口索引规则，不能仅替换模型类。

### 5.3 特征和模型选择顺序

先用固定模型比较特征，再固定入库特征比较模型；最后才在有限预算下做联合研究。每个阶段都有独立基线与 trial 记录，禁止把因子、模型、标签、调仓和费用同时调整后把改进归功于单一因子。

第一版不强制 Alpha158。选择 10–30 个经过 ETF 数据审计的动量、反转、波动、区间和流动性特征形成固定基线；Alpha158 可作为另一个有清晰字段依赖的对照。没有字段或缺少可信时间戳的特征不纳入。

## 6. 模型包与推断一致性

`ModelBundle` 包含权重、训练截止时间、标签成熟截止、特征名及顺序、特征版本、预处理器、缺失策略、训练池政策、horizon、代码版本和依赖版本。加载时先检查 schema 与版本，再预测。

序列模型与表格模型均输出统一预测契约，但可以有不同输入预处理分支；模型比较固定相同评价索引，并报告实际训练样本差异。ensemble 只能使用开发阶段的折外预测拟合权重，不得用训练内预测或 holdout 拟合混合权重。

## 7. 回测协议与指标

- 初始账户资金固定为人民币 500,000 元。第一版 t+1 开盘成交属于日频近似模型，不宣称精确还原集合竞价可成交量。
- 用户指定滑点 0.03%，按单边每笔成交解释：配置值 `0.0003`，买入价为参考价 × `1.0003`，卖出价为参考价 × `0.9997`。只在成交价格计入一次；佣金按用户最新确认0.03%（配置值 `0.0003`），按每笔单边成交额计收，暂不另加最低费用。例如参考价成交额为100,000元的买单，滑点后成交额为100,030元，比例佣金为30.009元（金额取整前）。最新费率覆盖此前千分之3；旧实验不追溯改写。
- 下单规模使用截至 t 的历史成交量/金额约束。当日总量可作为事后成交上限的模拟输入时，必须与决策输入隔离并明确这是日频近似。ETF Exchange 的同日双向成交按实际成交额累计共享历史参与预算；不以累计份额乘当前方向价格近似已用金额，调用者重置份额字典也不能恢复已用预算。
- 费用按佣金、最低费用、滑点等组成配置；涨跌幅、交易单位和可卖约束按 ETF 类型及生效日期建模，具体值在 G0 用交易所/券商资料核对。原始份额执行使用严格向下整手取整，避免 Qlib 默认加0.1份容差突破现金或参与上限；部分卖出按整手，全部清仓可保留企业行为产生的奇零/非整数份额。最低费用超过卖出所得与现金之和时不成交，比例佣金为零时仍正确执行最低费用约束。
- 主基准固定为沪深300指数，默认采用价格指数口径，W1 核实数据源、代码映射及开盘/收盘覆盖；缺失时阻止依赖该基准的正式评价，不静默替换为沪深300 ETF。策略净值按既定分红账本处理，报告中明确与价格指数的分红口径差异。相同历史池的等权策略和手工动量为辅助对照；已接入与模型相同的 Qlib ETF Exchange、风险/流动性/费用/调仓规则和独立账本。等权池选取全部当时合格且可买的标的，保留原单标的/跟踪组/换手上限；K 为权重上限时该上限继续生效。手工动量默认采用20个真实交易日的复权收盘收益，窗口由 benchmarks.momentum_lookback 冻结，缺报价或预热不足保留缺信号及覆盖率，不缩小评价日期。全部使用可比时间段和估值时点，并报告策略绝对收益。
- IC/Rank IC 以日期横截面计算，截面过小或标签常数时标记无效；保留统计样本数。
- 年化收益、波动、Sharpe、超额收益与回撤从组合日收益计算，明示年化交易日数与无风险利率假设。
- 记录换手、费用占比、持仓集中度、跟踪组暴露、未成交率和现金占比。进行基本费用、较高费用两档压力测试。实际回测已保存每日 execution.parquet，区分完全/部分/零成交，汇总买卖金额、佣金及价格内嵌滑点成本；金额加权成交率仅包含有可用原始参考价的订单，同时报告无价订单数。成本比例明确采用初始权益或成交额作分母；滑点归因不得再次从现金或日收益扣除。

正式回测前必须通过买入/卖出、停牌、费用、取整、分红和跨分段时点的人工小样本账本验证。可运行模型不等于已通过回测验收。


真实Tushare复权补齐可配置 `data.adjustment_path` 指向原始 `fund_adj` parquet（ts_code、trade_date、adj_factor）；按真实代码/日期对齐，不改原bin。必须覆盖实际报价，有限正值且唯一；与已存在因子冲突时报错。文件哈希纳入快照身份，研发/留出依然分离导出。事件来源覆盖和复权/原价一致性仍需完成，补齐文件不是G0豁免。


复权/企业行为关系已成为统一快照门禁（audit-data保存同一诊断）：相邻报价日因子倍率应与原价现金除息及显式份额事件相符，按登记日原份额换算现金；采用源码冻结的0.0005相对容差。缺事件的因子突变或错误现金单位拒绝；事件日无法检查时标记不完整并阻止发布。无报价间隔不以未知价格推断复权关系；源事件覆盖仍需单独确认。


## 实现补充：真实事件旁路与份额取整

`dividend_review_path` 只允许有主来源证据、原响应哈希与精确行计数的冲突重复排除，必须保留对应场内分红。`share_events_path` 为公告支持的非现金份额转换，含登记日、有效日、带时区公告时点、精确比例、`share_rounding`（none/ceil/floor/exact）与来源因子哈希；登记日为生效前一交易日。输入及主来源哈希纳入快照身份，映射后事件的时点、金额、比例和取整不得改变。

份额取整独立于交易手数；Qlib与独立账本同时应用，保存理论转换份额与取整份额差额。公司上进位补足产生的权益变化按新价格计入账户，不从现金扣作佣金；原provider和接口缓存保持只读。明确未知的交易方向状态禁止相应成交，缺报价日不前填状态；真实方向状态的模拟成交时点可用性仍需要来源证据。


## 除息参考价精度政策（真实异常修复）

可选data.reference_close_tick仅在已知源参考价精度时设置，最大0.001元；Tushare首轮配置显式采用0.001，其他配置默认None，原固定0.0005相对容差不变。依据基金报价最小变动单位及本地源参考价格点：[深交所基金交易单位说明](https://investor.szse.cn/knowledge/fund/trade/t20171113_538865.html)。这是精度处理政策，不声明接口提供了历史实际收件时点。

仅已声明事件日可采用精度路径：源reference_close必须为有限正值且落在声明价格点上，与按精确现金/显式份额事件计算的除息价相差不超过半个价格点（加float32数值误差），并且因子倍率与上一原价/源参考价的相对误差仍不超过0.0005。不满足任何条件即沿用原失败结果。审计、快照和全池汇总共享政策，DataSpec进入快照身份；报告保留原精确残差、有效残差、采用精度路径的事件数与例子。现金/应收/份额账本不舍入或改写来源金额，未知转换不得由价格比反推。

同日拆分后分红契约：现金默认按登记日原份额计量；仅公告支持时使用cash_share_basis=post_record_conversions，登记权益依次应用明确份额转换和ceil/floor，现金保持源值，除息估值按转换后每份现金扣减。share输入cash_basis_overrides必须精确绑定原分红event_id、现金、登记/支付日、转换event_id、主证据和后续sequence；映射、审计与快照禁止改写。159922的2024分红0.1292元按拆分后登记份额计算，不能用原份额乘0.1292或用未取整倍率代替真实登记权益。

公告的精确分配使用share_rounding=exact：十进制转换结果为整数时直接应用，不把整数拆分视为交易整手；非整数结果需要实际分配明细，不能猜测floor/ceil。嘉实四份和华宝二十份目标事前公告已明确映射，保留原公告、响应及因子哈希；来源字段来自公告，不从因子异常倍率推断。

G0报价成员覆盖补充：data.universe.metadata_quote_coverage逐条检查标准化quoted索引在历史成员中的known状态。缺成员行、unknown_historical_metadata、有效区间/可用时点未覆盖均计数；audit报告incomplete_quoted_historical_metadata，build_snapshot在暂存发布前拒绝完整目标快照，质量产物保存metadata_quote_coverage。resolve/build_history的诊断排除保持；已知outside_asset_scope和无报价未知窗口不误判为有报价成员缺口，无报价不推断运营/上市。
