# LLM 因子质量与 Token 效率优化总方案

日期：2026-09-21。状态：V1 L1/L2 工程与回放测试已完成；L3 真实 LLM 对照及 L4 研究确认未执行。本文件的效果目标仍须以实际 usage 和固定案例对照核验。

## 1. 目标与阅读顺序

目标是在因果、数据、选择门禁和可追溯性不退化的前提下，减少无效提案、重复搜索、错误修复和重复上下文。优化目标不是因子入选数量最大化，也不是提示词字符数最小化，而是每单位真实 LLM 用量获得更多可解释、可验证的有效实验。

## 4. Token 节省原则

1. 先用确定性程序归纳已有指标；第一版不增加每轮 LLM 总结调用或多智能体讨论。
2. 完整审计留本地；假设、提案、编码阶段分别收到完成各自任务所需的最小充分信息。
3. 摘要必须包含实际语义。哈希用于身份核验，不能代替模型尚未看到的规则、公式或事实。
4. 同时记录首次调用、修复、传输重试、失败和输出用量；不能只统计成功响应。
5. 程序缓存命中能避免新调用；服务商前缀缓存是否减少收费，依实际 usage 和计费规则核验。
6. 字符数、模型 tokenizer 计数、估计 token、服务商 usage 与货币账单分别记录。未知不是零。
7. 先建立固定案例集与质量门禁，再评估压缩比例。研究轮次上限与金额政策分离，沿用已授权 unlimited 金额政策。

## 5. 质量不退化的范围

冻结的标签、训练/选择划分、LightGBM、种子、成本、组合政策和入选门槛继续执行；完整决策使用原始精度指标。提示词摘要可以舍入显示，但近阈值状态必须显式给出，不能用舍入值重新判定。

原始数据和 v20 产物保持只读。优化代码产生新的代码哈希、运行 ID 和协议；不能恢复旧运行后悄悄切换提示词、门槛或计量策略。历史元数据延期是已有诊断边界，不因本优化被解释为正式 G0 通过。

独立留出、未来收益、账户凭据和原始异常敏感内容不能进入提示词、研究检索或错误修复。代码/数据失败、研究不入选、证据不足分别保存。所有候选都失败时，保留基线是正常结果。
