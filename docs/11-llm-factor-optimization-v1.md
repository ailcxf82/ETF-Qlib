# 第一版优化建议：保持三阶段，改善信息质量与 Token 效率

日期：2026-09-21。版本：V1。状态：L1/L2 已实施并通过零付费回放；真实 LLM 对照（L3）和研究确认（L4）未执行。以下 Token 数字仍是待实测的验收目标，不是已实现节省。

上级文档：[总方案](10-llm-factor-optimization.md)。实现细节见[工程规格](13-llm-factor-engineering.md)，验收见[测试标准](14-llm-factor-test-standard.md)。

## 1. 第一版决策

保留 hypothesis → proposal → code 三次正常逻辑调用，避免一次改动混入阶段合并、模型更换和研究策略变化。反馈由确定性代码生成，不新增常驻 LLM 分析调用。初次真实验收仍限定一个候选；其后用两轮小试验验证上一轮反馈确实进入下一轮。

第一版允许优化提示词信息组织、技术修复和用量测量；因子入选仍由现有完整五折、三种子、消融、风险和成本门禁判定。

## 2. 实施顺序

### V1-01 建立可复现的对照与计量

- 保存旧提示词生成器、案例快照、配置、完整源码哈希、序列化与 tokenizer 版本；当前脏工作区不能仅记录 commit。
- 分别统计逻辑请求、物理传输尝试、应用缓存命中、修复、输入/输出 token 和延迟。
- 优先读取服务商真实 usage；如当前 RDAgent 后端无法提供，明确标为 estimated 或 unknown，先验收本地输入体积，不宣布实际账单下降。
- Token 策略作为新版本研究配置冻结；不修改旧账本，不把金额 unlimited 改为虚构金额上限。

产物：对照清单、计量 schema、离线 usage 报告。验收：T01、T02、T14–T17。

### V1-02 保留完整假设并加强提案语义

- proposal 显式接收 hypothesis 与 reason；trial 同时保存假设、研究理由和验证后的提案。
- 提案增加 mechanism、direction_reason、failure_conditions、research_group；expected_difference 指向至少一个相关特征或明确的新信息类别。
- 不再提供可以直接照抄的 economics、algorithm、new information 占位文本；格式说明使用字段定义或完整有效的小示例。
- 确定性拒绝空值、已知占位值、hypothesis 与 factor_id 相同、不可用字段和时间口径矛盾。语言解释是否真实有效不能由长度检查证明；用固定案例人工盲评补足。
- direction 可以 unknown，但必须解释不确定性；新候选必须给出受支持的研究分组，现有 unclassified 记录按旧版本读取。

产物：提案契约 v2、格式/语义错误码、修复样例。验收：T03–T05。

### V1-03 构造分阶段上下文

本地完整 ResearchContext 保留；新增面向各阶段的 PromptContext 投影。

| 阶段 | 必须发送 | 默认省略 |
| --- | --- | --- |
| hypothesis | 任务/可见范围/诊断限制、可用字段语义、已有特征简表、选择规则、有限历史卡片 | 原始逐日数据、全部逐折逐种子明细、环境安装细节 |
| proposal | 完整当前假设及理由、相关特征公式、字段/时点/窗口契约、精简格式定义 | 无关历史指标和全量源码 |
| code | 已校验提案、所需字段、公式、时点、缺失与索引契约、许可库和执行限制 | 历史收益、无关特征、失败候选全集 |
| repair | 当前任务必要契约、待修复源文/代码、结构化错误和允许修复范围 | 无关场景描述、整份堆栈和重复历史 |

必需约束每次独立请求都发送；不依赖服务端记忆。proposal 若必须改变字段集合，应回到已冻结字段目录确认；coder 不自行新增字段或改公式。

字段说明书从审核过的映射读取，不通过名称猜测所有语义。特征说明书优先维护现有约 20 个基线特征的公式、窗口和分组，暂不建设通用知识图谱。

产物：可审计的提示词投影、字段/特征目录、长度与覆盖清单。验收：T06、T07、T18。

### V1-04 生成短而可行动的确定性反馈

每张摘要卡至少保留：身份、完整决策/原因、主要问题、各折种子中位数及离散程度、主要风险差异、覆盖/因果状态、相似特征、未知项和下一项可检验行动。

| 观察 | 建议的下一步检验 | 不应推断 |
| --- | --- | --- |
| 基线和候选均超风险上限 | 标记 inherited_baseline_risk，单独列出候选风险变化 | 候选独自造成全部超限 |
| 多折收益增量为零 | 标记 prediction_to_execution_diagnosis_needed | 因子一定没进入模型 |
| 跨种子正负不稳 | 记录区间，要求更稳定机制，维持拒绝 | 只保留表现最好种子 |
| IC 为负、模型增量不足 | 核查机制方向和模型利用方式 | 反号自动成为有效新因子 |
| 覆盖不足/运行错误 | 修复输入或实现并重新校验 | 经济假设已被否定 |
| 证据缺失 | 保留 unknown/inconclusive | 填零或虚构解释 |

每条事实指向本地证据 ID/哈希；提示词接收实际事实内容，路径仅保留本地。行动建议由规则表输出，第一版不声称具有完整持仓归因能力。完整 feedback 继续落盘，PromptContext 使用短摘要。

产物：feedback_summary_v2、确定性映射规则、v20 离线摘要。验收：T08–T11。

### V1-05 保存有限研究记忆并检查重复

- 卡片包含公式、机制、输入、方向、分组、结论、主要证据与失败原因，而非只有 factor_id。
- 首版同会话检索：最近 2 张卡片，加最多 3 张相关卡片；先合并去重，再受 token 预算裁剪。相关性采用字段/分组/窗口重叠的确定性规则，不增加 embedding 调用。
- 精确规范化后的公式重复在编码前识别；同名不同公式不误判为重复。任意 Python 语义等价不能靠字符串归一化证明。
- 因子取反、等价缩放及高相关的深度识别列入后续；首版可输出提示，不据不充分证据硬拒绝。

产物：本地研究卡片、确定性检索日志。验收：T12、T13、T19。

### V1-06 定向修复与实现验证

- 每阶段最多 1 次模型修复，每候选总计最多 2 次模型修复；若剩余额度不足，保存明确失败，不能自动开启新 trial 绕过。
- 捕获 JSON、结构、语法、索引和可修复运行错误；错误由可信执行器分类，输出 expected/observed/check_id 和有限脱敏信息。
- 未来引用、越权访问、公式实质变化、资源超限和传输不确定不是普通格式修复。未来依赖直接拒绝该实现；新经济定义必须新候选。
- 首版对支持的简单公式建立人工小样本 oracle，校验取值、符号、窗口、预热和最早依赖时点。任意代码仅通过因果检查不能证明实现了声明公式。
- v20 的 rolling(5) 叠加 close.shift(2) 在连续完整观测下首次有限输出需 7 行；明确 lookback 是含当日的输入跨度后验证声明，不改写旧产物。

产物：失败分类、修复前后差异、公式一致性测试。验收：T20–T24。

## 3. Token 预算初始建议

以下为首轮校准起点，单位是 tokenizer token，不是字符；采用一致 tokenizer 版本估算，服务商实际用量单独记录。实现必须先验证后端是否支持输出上限；不能仅在接收后截断冒称限制了生成费用。

| 阶段 | 输入软目标 | 输入硬上限 | 输出上限建议 |
| --- | ---: | ---: | ---: |
| hypothesis | 4,000 | 6,000 | 1,000 |
| proposal | 3,500 | 5,000 | 1,400 |
| code | 3,000 | 5,000 | 2,500 |
| 每次 repair | 3,500 | 6,000 | 依原阶段，最高 2,500 |
| 历史卡片合计（包含于阶段预算） | 1,200 | 1,600 | 不适用 |

压缩顺序：去除重复键和不必要说明 → 去除重复指标 → 缩减旧卡片 → 保留关键异常的折级摘要。必需约束、当前公式、字段语义、主拒绝原因和 unknown 标记不得裁剪。

仍超硬上限时返回 context_budget_exceeded，不发送残缺请求；由新版本预算配置扩容后开新会话。输出被截断时不得当作合法提案；计入失败/修复和实际用量。预算节省不能靠中途截断代码、删除失败轮次或隐瞒重试实现。

## 4. 发布与停止条件

1. 先通过确定性单元测试、无付费回放与 Docker/Qlib 集成，再进行有限真实调用对照。
2. 质量门槛优先；若 Token 降幅达标但语义、因果或恢复测试失败，不发布。
3. 正常候选仍 3 次逻辑调用；最多 2 次额外模型修复。SDK/传输重试另有统一上限与计量，不应叠乘失控。
4. 经济结果允许 rejected；不得为提高入选率改变选择门槛。
5. 新版未达到 Token 目标时，可认定工程通过但效率待优化；不可宣称已节省实际用量。

第一版完成后，再按[后续路线](12-llm-factor-optimization-next.md)决定是否增加诊断、合并调用或模型路由。
