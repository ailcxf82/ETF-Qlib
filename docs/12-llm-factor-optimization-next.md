# 后续优化建议：从反馈诊断到受控搜索

日期：2026-09-21。状态：V2-01、V2-03 与 V2-06 基础台账已实施并完成 L1/L2 回放；V2-02、V2-04、V2-05 和 V3 仍未实施。依赖[第一版](11-llm-factor-optimization-v1.md)完成并通过[验收](14-llm-factor-test-standard.md)。

## 1. V2：提高每次完整实验的信息价值

| 工作包 | 工程实现 | 验收重点 | 启动条件 |
| --- | --- | --- | --- |
| V2-01 信号到成交诊断 | 在 diagnostics 中关联因子、预测、调仓日排名、Top-K、目标仓位、成交/拒绝、现金及费用；用现有工件计算 | 人工夹具可分别识别信号未变、排名变但选池未变、订单受限、费用抵消；不将相关性标为因果 | V1 摘要稳定，相关工件完整 |
| V2-02 ETF 分组与状态诊断 | 按跟踪组、流动性组及事前定义行情状态报告预测和组合贡献；同时报告样本量 | 相似 ETF 不当作独立时间样本；状态定义只用当时可见数据；当前分类回溯标注诊断假设 | 分组语义已审核 |
| V2-03 跨会话研究检索 | 以 registry/trial 建本地索引，按协议族、字段、公式族、失败码检索；先关键词和结构匹配 | 重启仍能检索失败原因；不同快照/基线指标不直接排名；留出及敏感字段不能入库 | 同会话卡片测试通过 |
| V2-04 分级筛选 | 提案→重复→小样本实现→全量因子质量→完整配对；仅确定性不合法/确定重复可早拒绝 | 记录每级成本与淘汰原因；单因子 IC 低或相关高不直接淘汰潜在模型增量 | 统计各级瓶颈后实施 |
| V2-05 搜索配额与停滞管理 | 首批建议 6 个 trial，3 个独立机制、3 个有证据的受控修正；每次只改一个假设维度 | 所有尝试计数；失败也占配额；额度用完或无新可检验假设时停止，保留基线 | 新协议预先冻结配额 |
| V2-06 全项目搜索台账 | 聚合各会话已接触的开发期、候选族、提示词/模型版本、提案/修复/筛选数 | 新 run 不重置累计搜索次数；区分经济新候选、同定义技术修复和物理重试 | V1 身份和计量齐备 |

分组或行情诊断新增的发现仍属于开发期探索。不能看到某组表现好就改筛选池后继续使用原验收结论。假设变化需登记并在新实验中验证。

### 推荐候选方向

在现有可靠价格、成交量/额字段范围内，优先提出与已有特征具体不同且能被否证的机制：隔夜与日内收益分解、成交活跃度条件下的价格响应、趋势与下行波动的不对称关系。每种方向需说明为何现有动量/波动/流动性特征不足。

这些只是待检验假设，不是有效因子清单。份额申赎、溢折价、资金流、历史分类等因子，必须先具备对应可信且有时点证明的输入。

## 2. V2：独立推进计算效率

已有缓存优先复用，不重写另一套缓存系统。以下改动节省 CPU、I/O 或等待时间，应与 Token 节省分开报告。

1. 同一试验共享已核验 FeatureArtifact，减少百万行面板重复材料化；每个训练/回测仍保存独立 manifest。
2. 验证基线、候选和消融之间可复用的精确身份；任何复用必须包含数据、特征、模型、种子、协议、执行政策及依赖哈希。
3. 跨运行缓存仅在精确依赖清单、全部工件验证和取消/半成品测试通过后开放；不能为提高命中率直接删除全局 code_hash。
4. 细化基础/压力回测、持久化和缓存事件，并将嵌套进度汇总到首轮根目录；依据当前代码增量实施，已完成项不重复建设。

验收：同身份命中不重复计算；缺失或变更任一关键工件强制拒绝/重算；复用前后日收益与指标在既定容差内一致。

## 3. V3：用对照决定是否进一步减少调用

| 选项 | 预期收益 | 必须解决的问题 | 启用门槛 |
| --- | --- | --- | --- |
| 合并 hypothesis 与 proposal | 正常链路由 3 次逻辑调用降为 2 次，减少上下文重复 | 输出必须同时含完整机制与 FactorSpec；不能丢失假设审查 | 相同案例与研究预算下，质量不劣且全链路 token 实测下降 |
| 模型按阶段路由 | 简单格式修复/模板编码使用更便宜的模型 | 便宜不等于少 token；失败与升级重试可能抵消收益 | 明确模型版本、升级条件、全部调用用量及每候选成本 |
| 受限表达式/算子库 | LLM 输出短表达式，可信编译器生成代码并计算依赖跨度 | 支持范围可能限制因子机制；需要独立算子 oracle | 支持表达式精确等价、因果/预热测试通过，复杂定义明确拒绝或走原链路 |
| 按需 LLM 诊断 | 对确定性规则无法解释的失败增加一次分析 | 容易产生事后故事和额外 token | 明确触发器、事实引用、最大调用数；解释不得控制门禁 |
| Embedding 检索 | 在历史库变大后改善相似案例召回 | 引入调用、索引版本与召回不稳定 | 先证明结构检索不足；固定基准上收益超过新增成本 |
| 服务商前缀缓存 | 减少重复前缀的计费或延迟 | 不同提供商语义不同，缓存命中未必减少上下文 token | 真实 usage 区分 cached/uncached，不能把应用缓存命中混入 |

一次对照只改变一种策略。禁止同时合并调用、更换模型、放宽入选门槛后把差异归因于提示词优化。

## 4. 研究可信度与正式验收

- 当前 moving-block bootstrap 保留时间相关结构，但不消除自适应搜索的多重选择偏差。
- 先完善搜索台账，再评估 DSR/PBO 或其他选择偏差诊断是否适用；必须匹配收益统计量、依赖结构和试验定义，不能把新指标直接拼入任意总分。
- 为提示词或搜索策略比较预留开发内确认区间；其一旦被用于调优即标记为已使用。最终独立留出不参加提示词选择或 LLM 反馈。
- 同折三种子仅反映训练随机性，不是三段独立市场历史。推断按时间块/折报告不确定性。
- 历史成员、分类和可用时点证据继续按数据治理路线补齐；G0 通过前只报告诊断效果。
- 模型或风险政策研究单独建新基线和协议，不能让因子生成器自动改变交易条件。

## 5. 后续优先顺序

第一版 → 信号到成交诊断与跨会话研究卡片 → 有上限的多轮搜索 → 搜索偏差与确认实验 → 调用合并/模型路由。若实际计量显示输出 token 或重试占主导，则依据数据调整工程顺序，但不绕过质量门禁。

每阶段交付版本化代码、契约变更、对照报告、完整失败案例、用量分解、回滚方法。没有新增证据时停止重复测试和重复回测。

## 6. 2026-09-21 V2 本轮实现边界

- V2-01：`development_diagnostics` 读取同一配对实验已经落盘的 prediction、decision、execution 与 trade 工件，报告排名变化、选池/目标权重变化、成交受限和执行成本差。所有结论都标记为 `not_established`，不改变选择门禁，也不宣称因果。
- V2-03：新增本地跨会话研究卡片索引。按协议、快照、基线、字段和研究组进行确定性匹配；不同基线/快照卡片保留但标注 `comparable=false`，不参与数值排名。索引拒绝 holdout、密钥和路径类内容。
- V2-06：索引同时生成 append-only trial 计数、状态分布和提案计数，技术失败也计数。它不是 DSR/PBO 或独立确认的替代。
- 未实施 V2-02：当前 ETF 跟踪分类仍有历史回溯边界，不能将其升级为行情/分组经济结论。未实施 V2-04/05：应先依据新的诊断与台账冻结瓶颈和配额，而不是在本轮凭假设改变筛选或运行次数。
